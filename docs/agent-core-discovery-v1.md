# Agent Core discovery export v1

Agent Core now writes `agent-core-discovery-v1.json` alongside the existing
`agent-core-snapshot-v1.json`. The discovery file is additive and read-only;
the v1 snapshot serializer and all movement selection and run binding remain
unchanged.

Each agent record names the exact Agent Core and anchor grid IDs, then lists
the observed grids from the `GridLinkTypeEnum.Physical` group. Grid records
include world position and right/up/forward axes. Their block lists carry
entity ID, definition type/subtype, typed kind (`controller`, `camera`,
`sensor`, `suspension`, or `other`), grid-local cell position/bounds and
orientation, world center, and owner identity ID where exposed by the public
terminal-block API. Typed kinds come from the public block interfaces. A zero
owner ID is passed through as observed and may mean unowned or unavailable.
Share mode is reported as unavailable; actor access is marked
`not_evaluated_no_authenticated_actor`.

Suspension records also include additive read-only `hasSuspensionState`,
`steeringEnabled`, `propulsionEnabled`, `invertSteer`, and `invertPropulsion`
fields. These report current block configuration; they do not infer the sign
of steering relative to the vehicle or authorize actuator writes.

Blocks implementing the public `IMyMechanicalConnectionBlock` interface also
include the observed top-grid ID/name and attached/pending state. This is an
inventory of those observed interfaces, not a claim that all logical links
or every mechanically connected grid are covered. Grid membership is scoped
to the physical grid group. The export explicitly reports physical-grid,
typed-block, and mechanical-connection inventory completeness, observed
counts, and whether the agent list was truncated. Existing caps of 64 grids,
4096 block entries, and 8 agents still apply; incomplete flags must be honored
before interpreting missing entries as absent.

This makes exact controller/camera/sensor/suspension discovery available from
the Agent Core anchor. The worker resolves the explicitly selected physical
grid by entity ID and records its on-grid Core, controller, camera, and
suspension inventory in the immutable run context with the export run ID, tick,
and SHA-256. This worker step is only a timestamp-bounded precheck: age and
fingerprint do not prove that an export belongs to the currently running game
session. Activation, heartbeat, and approval carry the discovery tuple. During
mod preflight, the mod also requires the export run ID to equal the run ID
generated by the current session's own exporter instance; this rejects a
fresh-looking prior-session export. The host and mod recheck exact grid,
controller, camera, and Core entity IDs. Names remain descriptive metadata.

## Same-session preflight-only handshake

`vragecage run INSTANCE --discovery-only` creates a run with a random bootstrap
nonce and no queued command or preflight context. The launcher passes the
run, fixture, nonce, and pre-bootstrap exporter ID to the process. The mod
exports those bindings with its shared session ID and writes a `VWDR2`
`mod-ready` receipt only after reading back the discovery export. The plugin
checks the nonce, completeness flags, freshness, exact export hash, same
exporter run, and a nonempty observed grid inventory, then writes a matching
`host-ready` receipt. Stage-two activation binds the selected physical grid,
controller, camera, and Agent Core by exact entity IDs. Display names are
diagnostic metadata only. It refreshes the receipt while waiting so the worker
can reject stale exports.

`vragecage lab-command-activate INSTANCE` requires that exact worker service to
be active. Under the worker contract lock it checks both receipts against the
current complete export, creates one exact `preflight-only` operation and
immutable context, then publishes one exclusive `VWCA1` activation with a
90-second expiry. The plugin polls that file only while in discovery-only
mode. It checks the context hash, run/fixture/operation, session tuple,
current export, exact grid/Core/controller/camera, and the complete suspension
ID set before switching its in-memory command to `preflight-only` and writing
the mod activation. It then writes a `VWAA1` host acknowledgment.

The mod allows the bounded bootstrap wait, validates the stage-two envelope
against its shared session and exporter identity, verifies the exact export
hash and suspension IDs, and writes a `VWAA1` mod acknowledgment after loading
the immutable host activation. The worker accepts only matching acknowledgments
and times out if either is absent. Run, nonce, session, export, and operation
bindings prevent reuse across restart or replay.

The accepted action is fixed to `preflight-only`. That branch collects
preflight evidence and completes without invoking `ApplyOneBoundedStep`; the
handshake does not enable direct maneuver dispatch or vehicle movement. The
source builds and offline protocol tests pass. A live zero-output runtime
check remains unverified until a fresh isolated worker fixture and its current
discovery export are available.
